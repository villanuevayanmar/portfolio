# GitHub Upload Guide

Everything you need to push this portfolio to GitHub safely.

**Golden rule:** the file `.env.local` contains your secret keys and must **NEVER** be uploaded. It is already protected by `.gitignore` (rule `.env*.local`). This guide walks you through verifying that before your first commit.

---

## Before you start

Install [Git](https://git-scm.com/download/win) if you don't have it. Check with:

```bash
git --version
```

Also create a free account at [github.com](https://github.com) and sign in.

---

## Files that WILL be uploaded (safe)

These are your source code. GitHub needs all of them.

```
app/                       all pages + API routes
components/                all React components
data/content.ts            your site text (name, projects, skills)
lib/supabase/              Supabase client setup
supabase/migrations/       the SQL that creates your tables
.env.local.example         blank template (NO real keys)
.gitignore                 the protection rules
package.json               project + dependency list
package-lock.json          exact dependency versions
next.config.mjs
postcss.config.mjs
tailwind.config.ts
tsconfig.json
README.md
DEPLOYMENT.md
UPLOAD-CHECKLIST.md
GITHUB-UPLOAD.md           this file
```

## Files that must NEVER be uploaded

| File | Why |
|---|---|
| `.env.local` | Contains your real secret keys. Anyone with them can read/write your database. |
| `node_modules/` | Thousands of files, reinstalled automatically. Huge, useless on GitHub. |
| `.next/` | Build output, regenerated on every build. |
| `next-env.d.ts` | Auto-generated by Next.js. |
| `tsconfig.tsbuildinfo` | Auto-generated build cache. |

All of these are already covered by `.gitignore`, so Git will skip them automatically. The check below proves it.

## Step 1 — Verify your secret is protected

Open a terminal in the project folder and run:

```bash
cd "c:\Users\DELL\OneDrive\Desktop\Coding File\portfolio-next"
git init
git status
```

**Look at the output.** You should see `.env.local` is NOT listed anywhere. If you see it under "Changes to be committed" or "Untracked files", STOP — your `.gitignore` is broken and you must fix it before committing.

To double-check it's ignored:

```bash
git check-ignore .env.local
```

If it prints `.env.local`, it's safe. If it prints nothing, stop and tell me.

## Step 2 — Create the repository on GitHub

1. Go to [github.com](https://github.com) → click the **+** (top right) → **New repository**
2. **Repository name:** `portfolio` (or `villanuevayanmar-portfolio` — anything)
3. **Visibility:** choose **Public** (recruiters can see it) or **Private** (your choice)
4. **Do NOT** check "Add a README" / "Add .gitignore" — you already have those
5. Click **Create repository**
6. Leave the page open — GitHub will show you the exact commands under "…or push an existing repository from the command line"

---

## Step 3 — Commit and push

Run these one at a time in your terminal. Replace `YOUR-USERNAME` with your GitHub username and `REPO-NAME` with the name you picked.

```bash
cd "c:\Users\DELL\OneDrive\Desktop\Coding File\portfolio-next"

git init
git add .
git commit -m "Portfolio: Next.js site with Supabase tracking and contact form"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/REPO-NAME.git
git push -u origin main
```

When it asks for a password, GitHub no longer accepts your account password — you need a **Personal Access Token** (see below).

### Personal Access Token (one-time setup)

1. GitHub → your **avatar** (top right) → **Settings**
2. Scroll to bottom left → **Developer settings**
3. **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**
4. Give it a name, set expiration, and check the **`repo`** scope
5. **Generate token**, then copy it immediately (you won't see it again)
6. When `git push` asks for a password, paste this token instead

---

## Step 4 — Confirm it worked

1. Refresh your GitHub repository page — you should see all your files
2. **Critical check:** click into the repo and confirm there is **NO `.env.local`** file visible. If you see it, delete it immediately and rotate your Supabase keys (see the security note below).

## Security note

If `.env.local` ever gets committed by accident, the secret key is exposed. To be safe:

1. Delete `.env.local` from the repo and add it to `.gitignore` (already done)
2. Go to Supabase → Project Settings → API → **Reset** the `service_role` key to generate a new one
3. Update `.env.local` and your Vercel environment variables with the new key

Your keys:

| Key | Public or secret? |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Public — fine anywhere |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` / publishable | Public — fine anywhere |
| `SUPABASE_SERVICE_ROLE_KEY` | **SECRET** — never commit, never share |
| `ADMIN_PASSWORD` | **SECRET** — never commit |
