# Deployment Checklist — Must Upload / Configure

This is the exact, ordered list of everything that must be uploaded or
configured to get the site live on Vercel with a working database.

---

## A. Files that MUST be pushed to GitHub / uploaded

These files are part of the app and must be in the repository:

```
portfolio-next/
├── app/                        # ALL pages, layouts and API routes
│   ├── layout.tsx
│   ├── page.tsx
│   ├── globals.css
│   ├── not-found.tsx
│   ├── admin/
│   └── api/
│       ├── track/route.ts
│       └── contact/route.ts
├── components/                 # ALL React components
├── data/content.ts             # your content (name, projects, skills)
├── lib/supabase/               # Supabase clients
├── supabase/migrations/        # the SQL schema
│   └── 001_init.sql
├── package.json
├── package-lock.json
├── next.config.mjs
├── tailwind.config.ts
├── postcss.config.mjs
├── tsconfig.json
├── .gitignore
├── .env.local.example          # example ONLY (no real secrets)
├── README.md
└── DEPLOYMENT.md
```

## B. Files that must NEVER be uploaded

```
.env.local            # contains your real secrets
.env                  # same
node_modules/         # installed by Vercel automatically
.next/                # build output, generated by Vercel
```

These are already listed in `.gitignore`, so a normal `git add .` will skip them.

## C. Steps in order

### 1. Run the SQL in Supabase (do this first)
1. Supabase Dashboard → **SQL Editor → New query**.
2. Paste everything from `supabase/migrations/001_init.sql`.
3. Run it. Confirm the `page_views` and `contact_messages` tables appear under
   **Table Editor**, and that **RLS** shows as enabled on both.

### 2. Collect your Supabase keys
Supabase → **Project Settings → API**. You need:
- Project URL
- `anon` public key
- `service_role` secret key (keep private)

### 3. Push the code to GitHub
```bash
git init
git add .
git commit -m "Initial portfolio"
git branch -M main
git remote add origin https://github.com/villanuevayanmar/YOUR-REPO.git
git push -u origin main
```
> Do NOT push `.env.local`. It is git-ignored.

### 4. Create the Vercel project
1. Go to <https://vercel.com> → **Add New → Project**.
2. **Import** the GitHub repository you just pushed.
3. Framework preset should auto-detect **Next.js**. Leave build/output settings default.

### 5. Add Environment Variables in Vercel
**Project → Settings → Environment Variables.** Add each of these (Production,
Preview, Development):

| Name | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | your Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | your anon public key |
| `SUPABASE_SERVICE_ROLE_KEY` | your service_role secret key |
| `ADMIN_PASSWORD` | a strong password for /admin |

### 6. Deploy
Click **Deploy**. Vercel installs dependencies, builds, and gives you a live
URL such as `https://your-repo.vercel.app`.

### 7. Verify everything works
- [ ] Home page loads (Hero, About, Projects, Skills, Contact).
- [ ] Project filter buttons (All / Web / Console) work.
- [ ] Dark / light toggle works.
- [ ] Submit the contact form → success message appears.
- [ ] Supabase → **Table Editor → contact_messages** shows the new row.
- [ ] Visit `/admin` → enter your password → you see the page-view count increase.
- [ ] Supabase → **Table Editor → page_views** shows new rows (country appears
      once live on Vercel, because Vercel injects the geo headers).

---

## D. Optional: custom domain
In Vercel → **Project → Settings → Domains**, add your domain and follow the
DNS instructions it shows.

## E. Update the site metadata (optional but recommended)
In `app/layout.tsx`, change `metadataBase` to your real domain (e.g. your
Vercel URL or custom domain) so link previews resolve correctly.

---

## Quick troubleshooting

- **Contact form returns 500** → check the SQL ran and `NEXT_PUBLIC_SUPABASE_*`
  keys are set in Vercel (redeploy after adding env vars).
- **Analytics not showing a country** → country comes from Vercel headers and
  only works in production, not on `localhost`.
- **`/admin` always shows the login screen** → confirm `ADMIN_PASSWORD` is set
  in Vercel and you redeployed after setting it.
